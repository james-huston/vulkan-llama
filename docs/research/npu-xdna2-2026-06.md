# Research: Is the XDNA2 NPU viable for LLM serving on the HX 370 (Linux)?

**Date:** 2026-06-03 · **Method:** multi-source web research + 3-vote adversarial
verification (22/25 claims confirmed). **Hardware:** Ryzen AI 9 HX 370 (Strix
Point), Radeon 890M iGPU (RDNA 3.5, gfx1150), XDNA2 NPU (~50 TOPS), 96 GB RAM.

## Bottom line

**Use the NPU as a *complement* to the Vulkan iGPU — not the primary path (yet).**
As of **March 11, 2026**, XDNA2 NPU LLM inference became possible **on Linux** via
**Lemonade Server 10.0 + FastFlowLM (FLM) 0.9.35** — the first working end-to-end
Linux NPU path. The HX 370 qualifies (XDNA2). But the NPU runs only a curated
model zoo (not arbitrary GGUF), the NPU+iGPU "hybrid" mode is Windows-only, and
there is **no clean head-to-head NPU-vs-890M-Vulkan benchmark** to justify it as
the default. So: Vulkan iGPU = dependable GGUF workhorse; NPU = experiment to
benchmark and possibly route specific models to.

| 5 | NPU path exposes a real **OpenAI `/v1` API** (Lemonade `:13305`, FLM `:52625`), usable by opencode/LiteLLM. LiteLLM lists Lemonade as a provider. | high (3-0) |
| 6 | **Lemonade is a unified server** brokering BOTH the NPU (FastFlowLM) AND llama.cpp Vulkan/ROCm/CPU under one endpoint. Cross-platform incl. Docker. v10.6.0 (2026-05-21), active. | high (3-0) |

## Setup caveats (Linux)

- **IOMMU must be enabled** or the NPU isn't detected.
- Kernel ≥6.10 (or `amdxdna-dkms`), **NPU firmware ≥1.1.0.0**, raised `memlock` limits.
- **Known container bug** ([amdxdna #1771](https://github.com/amd/xdna-driver/issues), "No NPU device found" in Incus/containers) → NPU passthrough into Docker is unreliable. The Vulkan **iGPU** passes through fine via `/dev/dri`; the **NPU** likely needs bare-metal.

## Critical open questions (to answer by benchmarking — see story 001 Phase 2)

1. Measured FLM-NPU tok/s vs llama.cpp-Vulkan-890M for the same model/quant (7B–14B INT4/Q4)? No controlled benchmark exists.
2. Largest practical NPU model size on Strix Point (does it do 14B–30B usefully, or cap at ≤8B)?
3. Is any NPU+iGPU hybrid speedup reachable on Linux, or only NPU-only?
4. Does FLM support llama-swap-style hot model swapping + tool-calling / long context under opencode/LiteLLM?
